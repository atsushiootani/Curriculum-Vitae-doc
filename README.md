## 大谷篤史 ── AIエージェント・アーキテクト / バックエンド・アーキテクト

DDD・ドメインモデリングを軸にした堅牢な設計と、AIエージェント基盤の構築・生成AIを核にした "AIネイティブ" な開発の両方をリードできるエンジニアです。アーケードゲーム〜ブロックチェーン〜AI まで20年、技術スタックを越えてプロダクトの "中核" を設計と実装の両輪で作り続けてきました。

### 提供できる価値

- **AIエージェント基盤の設計・構築** — 複数エージェントのオーケストレーション、ツール連携、開発ワークフローへの組み込みまで、設計から実装まで一貫して担当
- **Agent Harness / エージェント実行基盤の構築** — 技術方針をポリシーとして定義し CI/CD で自動チェックする仕組み（Policy as Code / ガードレール）を作り、人手のレビューに依存せず組織全体で基準を担保する
- **AIネイティブ開発のリード** — 生成AIを "使う" だけでなく開発プロセスごと再設計し、チームの開発速度を底上げする
- **設計力（DDD / アーキテクチャ）** — 境界づけられたコンテキストに基づく設計、モノリス↔マイクロサービスの判断、分散トランザクション設計
- **幅広い技術領域** — C++/3D物理 → モバイル → TS/Go/Rails → Solidity/Cadence → Unity。新領域の立ち上げを任され続けてきた
- **チームの底上げ** — コードレビュー、メンタリング、ドキュメント文化・開発文化の醸成

### 貢献できる領域

- AIエージェント / AI活用基盤の設計・立ち上げ
- AIネイティブ開発体制の構築・推進
- 0→1 の技術選定・アーキテクチャ策定、既存プロダクトの設計改善

業務用ゲーム（アーケード） → コンシューマゲーム（家庭用） → モバイルソーシャルゲーム → iOS/Android → バックエンド → ブロックチェーン → 設計・アーキテクチャ → **AIエージェント / AIネイティブ開発**

# 職務経歴

## Aidea ── AIエージェント連携 macOS ネイティブワークスペース（個人開発 2026/04 ~）

Claude Code を中核に、複数の AI エージェント（コンパニオン）を協調運用するための macOS ネイティブアプリを、**立案・設計・実装まで一人で**手がけています。Aidea 自体の開発も Aidea 上で行う（ドッグフーディング）ほか、YouTube チャンネル運営・技術ブログ執筆など、実務の基盤として日常的に使用しています。

**技術スタック**

- Swift 5.9+ / SwiftUI / WebKit / SwiftTerm（macOS 15+ ネイティブアプリ）
- Claude Code（エージェント実行基盤）、VOICEVOX（音声合成）

**担当業務 / 設計のポイント**

- 1 ワークスペースにつき最大 9 体のコンパニオンを役割分担（開発 / レビュー / 定時タスク / ドキュメンテーション / パイプライン構築・実行 など）させ、ハンドオフでタスクを受け渡すオーケストレーションを設計・実装
- セッションをまたぐコンテキスト永続化、音声入出力（VOICEVOX 読み上げ）、作業ログ記録など、エージェントを "継続運用" するための周辺機構を実装
- cron トリガーによるスケジューラ、コードスニペット widget とスケジューラの双方向変換ブリッジなど、定型業務を自動化する基盤を構築
- WebKit による本物のブラウザ挙動（OAuth・位置情報・permission API）を確保するため、Electron webview の制約を避けて自作ネイティブ化を選択
- 段階的開示でコンテキスト消費を抑えるスキル / 指示の設計、ADR（設計判断記録）・仕様ストックなどドキュメント駆動の開発体制

**観点**

- マルチエージェント設計、ツール連携、「どこまでを AI に任せ、どこを人間が握るか」の役割分担の設計思想
- ネイティブ（Swift / SwiftUI / WebKit / SwiftTerm）の実装力と、AI 開発フローの設計力の両立

**担当業務 / 設計のポイント**

- **技術ガバナンスの仕組み化（開発ハーネスの構築）**
    - マルチプロダクト体制で、CTO の技術方針が各プロダクトに行き渡らず、判断が属人化していた
    - 方針を**ポリシーとして定義**し、**CI/CD で自動チェック**する仕組みを構築

### デッドストームパイレーツ(2008/10 ~ 2010/4)

- アーケード用ゲーム
- 2人乗りライド型筐体のガンシューティング
- [https://www.youtube.com/watch?v=XTF9yzWm8oE](https://www.youtube.com/watch?v=XTF9yzWm8oE)

**技術スタック**

- PS3互換基盤のSYSTEM357。後にPS3に移植も担当しました

**チーム状況**

- エンジニア10~20人

**業務の詳細**

<details><summary>詳細を表示</summary>

- 最初はリグを実装しました
    - キャラクターの髪や服の裾が、風や重力、キャラのモーションによって自然に揺れる表現です
    - ボーン（骨）の一本一本にかかる力や慣性力を計算し、隣の骨との影響を計算し、自分の体にめり込まないよう当たり判定の計算と押し出し処理を計算し…というのを3D計算しました
    - 骨の設定や、当たり判定の登録などをデザイナが Maya で登録できるようにし、データの出力とランタイム読み込み実行を行う処理も行いました。（python で記述する Maya ツールの部分などテクニカルアーティストの人と協力）
    - 当初は社内の格闘ゲーム等で使われていたプログラムを引き継ぎましたが、最終的にはほぼすべて一から書き直しました
    - この時実装したプログラムはのちに社内の共通ライブラリに取り入れられました
    - 3D物理計算と行列計算を伴う、高度な物理・数学の知識が求められる難度の高い実装でした
    - キャリアの現時点においても、プログラミングのタスクとしてこれより難度が高い仕事には未だ出会っていません
- レース部分
    - 自機である海賊船を、舵輪型コントローラで制御し動かすミニゲームがあるのですが、その処理全般を実装しました
    - 船が舵を切った時の自然な動きと、ゲームとしてわかりやすく気持ちいいケレン味のある動きとの両立点を探りました
    - 岸壁に衝突して強制的にコースに戻すなどの処理や、岸壁データの作成、読み込み周りを丸ごと作りました
    - 先輩からは「レースゲームを1本作るのとほぼ同等の仕事」と評されました
- UI
    - ゲーム中のさまざまなUI表示を実装
- クレジット
    - 100円玉を入れるとプレイ回数が1回分増えるといった処理のことです
    - コンティニュー受付の終了間際に100円硬貨が投入された場合の扱いや、2人プレイ時にどちらのクレジットとみなすかなど、金銭が直接関わるため見た目以上に慎重さが求められる部分です。決済系 API を扱う場合と同等の厳密さが必要でした
    - アーケードゲーム特有の問題点をハードウェア面も考慮しながら要件定義と実装しました
        - 安全性の面です。筐体（ゲーム機）が揺れるゲームのため、プレイヤーがお金を入れ（ようとしていると思われ）る時は揺れを止めるなどの制御も同時に行う必要があります
    - この時書いたのはフローチャート程度でしたが、設計をしっかり固めてから実装に入るということを最初に意識した仕事でもあります
- 立体視対応
    - 当時立体視が流行っていたこともあり、ゲームの立体視対応を行いました
    - 立体視に対応するライブラリが存在しない時期だったため、射影変換行列を右目用・左目用に変換する計算を自力で実装しました（剪断変換の概念もこの時に習得しました）
        - オブジェクトの座標をカメラ視点の座標系に変換する処理のことです
        - 立体視は人間の両目の視差の分（約60〜70mm）だけずらすのですが、これはスクリーンのサイズに関わらず固定となるため（つまり画面に直接ものさしを当てて60mmずれるように映す必要がある）、テレビに映すか巨大なスクリーンに投影するかで射影変換行列のパラメータが変わります
- モーションコントローラ対応
    - PS3 移植版はモーションコントローラ対応での発売だったため、その対応も担当しました
- 全体として、難度の高い課題の多いプロジェクトでした
    - 新卒当時はそれが当然と捉えていましたが、その後のキャリアでこれ以上に難しい課題にはほとんど遭遇していません。高いレベルの課題を新卒の私に任せ続けてくれた当時のマネージャーに感謝しています
